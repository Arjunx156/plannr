# 4. PGlite in development and tests, Neon in production

**Status:** accepted, October 2026

## Context

The server needs real Postgres: JSON columns, transactions and the same SQL in every environment. Asking a
contributor to run a database server before `bun run dev` works is a poor first five minutes, and tests that
share one database leak state into each other.

## Decision

The server talks to one Drizzle type, `Db` (`server/db/types.ts`), with two implementations:

- `server/db/local.ts`: PGlite, Postgres compiled to WebAssembly, in memory. The dev server runs the API inside
  Vite on it (`server/vitePlugin.ts`), and the tests run on it too, so no test touches a shared database.
- `server/db/neon.ts`: Neon's serverless driver, for the Vercel function in production.

Both run the same migrations from `server/db/migrations/`, generated by drizzle-kit.

## Consequences

- `bun install` and `bun run dev` give a working app with accounts, shared links and history, and no setup.
- Tests that need their own database pay a few seconds for PGlite to boot, so they carry a longer timeout
  (`OWN_DB_MS` in `tests/server/fixtures.ts`).
- The two drivers' Drizzle types differ in details the code never uses, so each module casts once to `Db`, with
  the reason beside it. These are two of the eight allowlisted casts in `scripts/structure.ts`.
